# 屏幕视频播放器使用说明书

适用设备：Waveshare ESP32-P4-WIFI6 开发板 + WX101BH020I-40Z 屏幕

适用电脑：Windows；首次使用先按仓库 README 配置 ESP-IDF 5.5.5、FFmpeg 和转码 Python，并填写 local-config.ps1。文中的 C:\projects\esp32p4-mjpeg-player 是示例仓库位置，请替换成自己的位置。

**每次换视频，只需要：放入 MP4 → 接数据线 → 输入一条短命令 → 等待屏幕播放。**

## 一、先记住这条命令

    .\play.cmd "test.mp4" 5

它的意思是：找到 MP4 文件夹中的 **test.mp4**，取开头 **5 秒**，写入开发板，然后不断循环播放这段内容。

- 把 **test.mp4** 换成你自己的视频文件名。
- 把 **5** 换成你想截取的秒数，只能填写大于 0 的整数。
- 默认使用 **COM7** 下载端口。
- 文件名始终放在英文双引号中，中文、空格也可以使用。
- 5 秒不是只播放一次就关机，而是“这段 5 秒的视频反复播放”。

## 二、第一次照着做

### 第 1 步：放好视频

打开文件夹 **C:\projects\esp32p4-mjpeg-player\mp4**，把想播放的 MP4 复制进去。

例如，文件完整路径为：

    C:\projects\esp32p4-mjpeg-player\mp4\test.mp4

命令中只填写 **test.mp4**，不需要填写前面的文件夹路径。文件夹可以放多个 MP4，每次通过文件名选择其中一个。

如果看不到文件名结尾的 .mp4，在资源管理器中打开“查看 → 显示 → 文件扩展名”（不同 Windows 版本菜单位置可能略有差别），避免误写成 test.mp4.mp4。

### 第 2 步：连接开发板

1. 保持已验证正确的屏幕接线。
2. 用能传输数据的 USB 线，将电脑连接到开发板的 **CH343 下载／串口接口**。
3. 如果 VS Code 的串口监视器还开着，先点击该终端，按 **Ctrl + ]** 退出，释放串口。

日常只换视频，不需要重新插拔屏幕排线。

### 第 3 步：打开 PowerShell 并进入工作目录

在 Windows 开始菜单中搜索 **PowerShell**，打开后输入：

    cd C:\projects\esp32p4-mjpeg-player

按回车。看到提示符类似下面这样，就说明目录正确：

    PS C:\projects\esp32p4-mjpeg-player>

**不要把 PS C:\projects\esp32p4-mjpeg-player> 这段提示符一起复制进命令。**

### 第 4 步：输入短命令

播放 test.mp4 的前 5 秒：

    .\play.cmd "test.mp4" 5

按回车，等待即可。首次完成本机工具配置后，使用这个入口不需要再手动输入脚本放行命令，也不需要手动打开 VS Code 编译。

### 第 5 步：等待完成并观察屏幕

终端会按顺序显示三个阶段：

| 阶段 | 电脑正在做什么 | 你需要做什么 |
|---|---|---|
| [1/3] 转码 | 截取指定片段，转换成开发板能播放的格式，并检查容量 | 等待 |
| [2/3] 编译 | 生成播放器程序，分别检查程序和视频的容量 | 等待，首次可能需要几分钟 |
| [3/3] 烧录 | 通过数据线写入分区表、播放器程序和视频 | 保持连接，不拔线、不关闭窗口 |

看到 **“烧录成功”** 后，程序会请求开发板复位并开始自动循环播放，**不用输入 n 或 p**。

以屏幕实际出现所选视频为最终成功标准。如果只看到“编译通过”，还不能说明视频已写入开发板。

## 三、以后怎么换视频

以后只需重复下面三件事：

1. 将新 MP4 放入 **C:\projects\esp32p4-mjpeg-player\mp4**。
2. 连接数据线，退出串口监视器。
3. 在 C:\projects\esp32p4-mjpeg-player 目录中运行短命令。

| 你想做什么 | 输入的命令 |
|---|---|
| 播放 test.mp4 的前 5 秒 | .\play.cmd "test.mp4" 5 |
| 播放中文文件名视频的前 3 秒 | .\play.cmd "我的视频.mp4" 3 |
| 播放带空格文件名的视频 | .\play.cmd "我的 视频.mp4" 5 |
| 端口变成 COM8 | .\play.cmd "test.mp4" 5 COM8 |

每次成功烧录后，**板上原来的视频会被新视频替换**。当前版本一次保存并循环播放一个片段，不会自动轮播文件夹中的所有视频。

**时长必须同时满足：不超过原视频长度，且转码后能装入 29 MiB 视频分区。** 不是所有视频都能截取相同长度。

## 四、几个常见问题

### 为什么要“转码”？我需要自己转换 MP4 吗？

不需要。你只提供 MP4 即可。

MP4 是一种封装格式，里面通常是 H.264 等编码。当前播放器使用 MJPEG AVI，可以理解为依次解码和显示一连串 JPEG 图像。工具会自动完成转换，你不需要准备照片，也不需要手动操作 FFmpeg。

### 视频播放参数能随便改吗？

日常用户只修改文件名、时长和必要时的串口号。当前预设为：

| 项目 | 当前设置 |
|---|---|
| 素材帧率 | 30 fps，即目标每秒 30 帧 |
| 视频区域 | 1280×720，等比例适配，不拉伸、不裁切 |
| 屏幕画面 | 横屏 1280×800，多余区域补黑边 |
| 声音 | 无声 |
| 取片位置 | 从原视频开头开始 |
| 播放方式 | 循环播放，断电后重新供电仍自动播放 |

30 fps 是素材目标，实际播放速度还要通过画面及运行日志确认。帧率、分辨率和压缩参数由工程维护者预设，普通用户不用修改。

### 提示“视频文件过大”怎么办？

把命令里的秒数调小，再试一次。例如先从 5 秒改为 3 秒：

    .\play.cmd "test.mp4" 3

判断依据是 **所选片段转码后的大小**，不是原 MP4 文件大小。同样 5 秒的视频，画面不同，转码后的体积也可能不同。

板上总 Flash 为 32 MiB；目前分为 **2 MiB 播放器程序分区 + 29 MiB 独立视频分区**，其余空间用于启动、配置和保留。视频单独保存，不再塞进程序文件。工具不会自动扩大分区，也不会擅自降低画质、帧率或缩短你填写的时长。

容量检查失败时会停止，不会继续烧录。编译时也会分别检查程序与视频分区容量。增加视频空间后，可容纳更长片段，也为以后提高转码画质留出空间；当前视频预设仍为 1280×720、30 fps，压缩质量保持不变。屏幕原生横向分辨率为 1280×800，增加存储不会增加屏幕的物理像素。

**首次使用分区分离版，需要运行正常的 play.cmd 命令完整烧录。** 它会将新分区表、播放器程序和视频一起写入；不要只单独烧录应用 bin，也无需执行全片擦除。原有 NVS、PHY 分区及程序起始地址保持不变。较长视频写入时间也更长，请等待完成。

测试片 sample-video-1280x720-5mb.mp4 的完整 20 秒已通过转码和编译检查，转码后约 26.01 MiB，共 600 帧。可运行以下命令烧录并测试：

    .\play.cmd "sample-video-1280x720-5mb.mp4" 20

此分区分离版尚未进行实机播放验证；烧录后应确认画面正常、每轮 600/600 帧、耗时接近 20 秒。不代表所有视频都支持相同时长，是否装得下仍以转码结果为准。

### 播放时必须一直连接电脑吗？

更新视频时需要连接电脑。成功烧录自动播放版后，只要保持适当供电，就可以独立循环播放，不需要电脑持续运行。

### 短命令为什么不会再提示禁止运行脚本？

play.cmd 会在内部以“仅本次运行放行”的方式启动 PowerShell 脚本，不会永久修改系统执行策略。以后直接使用短命令即可。

## 五、报错时看这里

| 终端提示或现象 | 你应该怎么处理 |
|---|---|
| 请先复制 local-config.example.ps1 / 找不到转码 Python | 按仓库 README 完成一次性工具配置；local-config.ps1 中填写 IDF 初始化脚本、Python、FFmpeg 和 ffprobe 路径 |
| 找不到视频 | 检查视频是否在 C:\projects\esp32p4-mjpeg-player\mp4；核对文件名、扩展名和引号 |
| 找不到串口 COM7 | 检查数据线、下载接口；在设备管理器的“端口（COM 和 LPT）”中确认实际端口，再填写到命令末尾 |
| 串口被占用／无法打开串口 | 退出 VS Code 或其他软件的串口监视器，再重试 |
| 视频文件过大 | 缩短秒数后重试 |
| 播放时长超过原视频长度 | 填写不大于原视频长度的整数秒 |
| 秒数无效 | 使用 1、3、5 这样的正整数，不填写 0、负数、小数或“5秒” |
| 无法识别 play.cmd | 先执行 cd C:\projects\esp32p4-mjpeg-player，核对 play.cmd 是否存在；命令前要有 .\ |
| 只出现英文 Usage 提示 | 参数没有写全，按 .\play.cmd "test.mp4" 5 的形式重新输入 |
| 拒绝访问 clip.avi | 先关闭正在预览该工程视频的窗口，并确认没有其他转码／编译任务；若仍失败，保留完整报错交给维护者检查权限 |
| 编译失败 | 停止操作，保存错误截图和下方所列构建日志，不要手动烧录旧文件 |
| 烧录失败或中途断线 | 修复数据线、供电或串口占用问题后重跑完整命令；此时可能只写入了一部分内容 |
| Video partition missing / Video data missing or mismatched | 程序与视频未完整配套写入，重跑完整 play.cmd 命令，不要只烧录应用 bin |
| 显示烧录成功，但黑屏、花屏或视频不对 | 保留屏幕照片和终端输出，交给维护者排查；不要仅凭烧录成功认定播放正常 |

构建日志位置：

    C:\projects\esp32p4-mjpeg-player\project\flash_video_mvp\logs\workflow_build.log

## 六、可选：只检查和编译，不写入开发板

如果想先确认视频能否装下，可以运行：

    .\play.cmd "test.mp4" 5 -BuildOnly

这个模式会转换视频并编译程序，**不会连接串口或烧录开发板**，但会更新电脑上的工程素材和固件。以后真正要更新屏幕时，再运行不带 -BuildOnly 的命令。
